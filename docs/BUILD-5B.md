# Build 5B — Growth Experiment Engine

Completed within the local, single-browser prototype scope. Final acceptance: 2026-10-03. This report supersedes Build 5A's deferred experiment boundary.

1. **What was built.** Growth Lab now supports Idea → Hypothesis → Experiment → Measure → Learn → Decide. Portfolio and detail routes are `/scale/experiments` and `/scale/experiments/[id]`; Scale home, ideas, constraints and levers expose related evidence.
2. **Experiment model.** Separate lifecycle (draft, ready, running, paused, completed, cancelled), result (win, partial, no effect, negative, inconclusive) and management decision. Records include stable ID/code, ownership, relationships, planned dates, actual timestamps, confidence, execution notes, blockers and start snapshot. Domain modules live in `lib/scale/experiments`; UI is split across editor, measurements, review and portfolio/detail components.
3. **Idea conversion.** A ready idea passing readiness checks creates a linked draft. Starting explicitly moves the idea into experimentation and records history; creating a draft does not erase the source idea.
4. **Hypothesis.** Structured change, audience, expected movement and rationale fields make assumptions inspectable.
5. **Design.** Intervention, audience, channel, sample, comparison and notes describe execution. Starting freezes the design; notes and lifecycle actions remain available where permitted.
6. **Growth Metrics.** Fourteen initial metric definitions plus manual/custom definitions and read-only Strategy KR/System KPI references. A primary metric and optional secondary guardrails carry unit, category, direction and source metadata. Source values never silently become experimental observations.
7. **Baseline and criteria.** Baseline value, period, source, target, optional minimum threshold, tolerance and written criteria are explicit. Numeric direction/threshold validation prevents contradictory criteria. Binary metrics use a baseline exception. Date inputs use the browser's Gregorian date control.
8. **Measurements.** Running experiments accept dated observations with notes. Append-only history shows baseline and previous-observation deltas; the simple chart includes applicable baseline, target and minimum references. Missing data stays missing. Corrections require a new observation; there is no destructive history editor.
9. **Evaluation.** Direction-aware increase/decrease, maintain-level and binary rules suggest a result from the latest primary observation. Tolerance distinguishes unchanged results; inadequate evidence can remain inconclusive. This is a transparent management heuristic, not statistical significance or causal attribution.
10. **Confirmation.** Suggestions do not automatically finalize results. Completion requires a manager-selected result, rationale, explicit confirmation, learning and decision. Without primary evidence only inconclusive completion is allowed.
11. **Learning.** Completion stores linked learning, supporting evidence, insight and confidence. Learning is separate from the metric and survives later iterations.
12. **Decisions.** Scale, iterate, retest, continue monitoring, stop and archive are explicit decisions with rationale. Completion atomically records result, learning and decision. Scale requires explicit capacity and Strategy alignment reviews.
13. **Iterate / Retest.** Eligible completed decisions create a new draft with a new ID/code and parent reference. Dates, observations, completion, final result and start snapshot are cleared; reusable hypothesis/design fields are retained for editing.
14. **Lineage.** Parent/child navigation makes revisions inspectable. Creating a child does not rewrite its completed parent.
15. **Idea validation.** A completed linked experiment enables a reasoned, audited idea review: validated, rejected or under review. A win does not automatically validate an idea. The UI acceptance scenario deliberately left the idea under review.
16. **Constraints.** Experiments retain constraint relationships; constraint pages show experiments, result distribution and learning. A successful experiment does not automatically resolve a constraint.
17. **System capacity.** Relevant process health, independence and dependency evidence is read-only. Missing evidence is explained. Scale requires review acknowledgements rather than an unexplained score gate. The decision stores the reviewed source context.
18. **Strategy alignment.** Linked Objective/KR/cycle references remain read-only. Start snapshots preserve relationship IDs; completion context captures reviewed Strategy evidence. Later source edits do not replace stored decision context.
19. **Quality.** Explained weighted completeness checks cover hypothesis, design, metric, baseline/criteria, ownership, relationships and comparison/guardrail evidence. Quality is readiness guidance, not a probability of success.
20. **Needs Attention.** Growth Lab highlights ready-but-unstarted work, stale primary measurements (configurable days), approaching/overdue experiments with too little evidence, incomplete completion evidence, capacity concerns on wins, repeated negative lever outcomes and older active constraints lacking recent learning. Calendar checks use Tehran days.
21. **Historical integrity.** Started design and metric definitions are frozen. Closed experiments are immutable. Measurements, learnings, decisions and idea reviews are append-only. Runtime transition checks also protect the general persistence path; lineage cycles and invalid references are rejected.
22. **Persistence.** Optional `experimentData` extends the existing `growth-engine.scale.v1` store. Existing Build 5A records remain valid; fallback metric definitions do not manufacture experiments or measurements. System, Strategy and Assessment stores are not written. Storage remains origin-specific browser storage with no server backup or multi-user guarantee.
23. **Tests/results.** 401 tests passed, zero failures: 368 previous plus 33 experiment tests. Coverage includes requested A–Y scenarios, tolerance/directions, missing evidence, threshold validation, start/closed-history guards, lineage, migration, Scale review and persistence bypass protection. TypeScript and production build passed. The production server restarted successfully on 2026-10-03.
24. **Browser QA.** On isolated localhost, a ready idea became EXP-1; baseline 10, minimum 15, target 20 and observations 14/17 produced a confirmed partial result, learning and Iterate decision. EXP-2 preserved lineage, reset execution history, measured 22 and produced a confirmed win. Scale completion was blocked until both review acknowledgements were checked. The capacity warning was visible; stored context and the original experiment's history remained intact after refresh. Idea review remained explicit and the constraint remained active. Desktop, tablet and mobile screenshots were reviewed. Seven routes at widths 390/820/1440 had matching document/client widths (no page overflow); the measurement table scrolls within its own region on narrow screens. Tab entered the metric drawer and Escape closed it with focus restored. Missing experiment IDs show a recovery link. No captured console warnings/errors or hydration errors remained. Seven page routes and 20 referenced Next assets returned HTTP 200. Temporary viewport override was reset.
25. **Dependencies.** No dependency added; existing Next.js/React/TypeScript and test infrastructure are used.
26. **Issues encountered.** The local server had stopped during the paused session; restarting restored service. Browser binding required an explicit browser ID during earlier QA. No unresolved application failure was found in the exercised paths. Results remain manually interpreted observations: sample comparability, collection quality and causal confidence require management judgment. The chart is intentionally simple, and the prototype has no external analytics ingestion, authentication or backend.
27. **Build 5C boundary.** Full funnel analytics, growth loops, the final Scale executive dashboard, statistical testing, automated attribution, AI and external integrations remain unimplemented. Their exact next-build scope requires a separate specification; this release closes the experiment/measurement/learning/decision engine only.

Local entry: http://localhost:3000/scale/experiments. Test data was created on localhost; the separate 127.0.0.1 browser store was preserved.
