# Build 4E — Monthly Adapt, Learn, Cycle Reset

## Completion report

1. **Built:** `/strategy/adapt`, `/strategy/adapt/[reviewId]`, `/strategy/cycles/[id]/adapt`, and `/strategy/cycles/[id]/learn`. Navigation, Strategy landing, KR/Objective audit history and Initiative learning history are integrated into the existing application.
2. **Monthly model:** period, reviewer, progress summary, external/internal changes, risks, decisions, resource shifts, priority/initiative reviews, next focus, notes and completion timestamps. A completed review contains a detached evidence snapshot. Overlapping review periods are rejected.
3. **Stalled KR:** three actually recorded, consecutive completed weekly reviews, stable movement and progress below 100%. Missing weeks and incompatible measurement definitions interrupt comparable progress. Thresholds are in `lib/strategy/adapt/types.ts`.
4. **Repeated blocker:** same KR, three consecutive completed weekly records, nonempty text equal after whitespace and Persian/Arabic character normalization. No semantic inference or fabricated history.
5. **Confidence decline:** three consecutive non-null confidence observations, each lower than its predecessor, with at least a two-point total decline. Missing observations do not imply a trend.
6. **Initiative adaptation:** continue/support/reduce/pause/stop/replace/extend/owner decisions, rationale, effective date and applied timestamp. Saving a decision does not execute it. Stop/pause/owner/extension have explicit application; support/reduce/replace remain management records, not an automated task or resource-management engine. Applied decisions cannot be rewritten.
7. **Resource shifts:** source, destination, resource category, description, rationale and optional Objective/Initiative links. Categories include money, people, management attention, time and other. No accounting or external allocation is performed.
8. **Priority history:** rank/status/rationale edits retain old/new values and source review. A rank collision swaps the peer's rank and audits both records. Priority validity/focus assessments are separate from applying rank/status changes.
9. **Objective/KR control:** reason, open source review and explicit confirmation for changes in started cycles. KR editor supports coordinated definition/type/milestone edits using the same audited path. Changing a definition during an open weekly check-in is rejected; the next weekly period starts a comparable segment using the revised baseline. Initial setup in an unstarted draft cycle remains editable. Started cycles cannot downgrade to draft to evade controls.
10. **Adapt quality:** 25% material risk acknowledgement, 25% important active Initiative review, 20% decision clarity, 15% resource/priority review and 15% next focus. Incomplete quality requires an override reason; it is not a business performance score.
11. **Cycle review:** explicit achieved/partial/missed/cancelled classifications for every Objective and KR, final measurements, confidence, recorded weekly evidence, wins/misses, Initiative learning and executive conclusion. Classification is mandatory even with an override. Other unresolved review warnings can be accepted with a reason.
12. **Learning:** first-class categorized Strategy learning with evidence and optional entity links. Initiative learning records hypothesis support, lesson and repeat/stop/reconsider judgement independently of execution progress.
13. **Assumptions:** strategic statement, evidence and untested/supported/weakening/invalidated status, separate from an Initiative's impact hypothesis. Completed cycle snapshots retain the recorded assumptions and lessons.
14. **Carry forward:** explicit selection of priorities, Objectives, KRs, unfinished Initiatives, learnings and assumptions. Required parent selections are checked, never selected silently. Selection and old/new ID mappings are stored.
15. **Reset:** a new draft cycle; new IDs and dates; numeric KR baseline equals the frozen final value and requires a new valid target. Binary/milestone results restart; confidence and Initiative actual-effect/execution history reset. Source data comes from the completed cycle snapshot rather than later live edits. No weekly check-ins/reviews/snapshots are copied.
16. **Historical integrity:** completed Adapt and Cycle reviews, change records and reset records cannot be rewritten through the provider. Completed/archived cycles reject changes to their business and review collections. Closing is a separate confirmed action after review completion; there is no reopen control for closed cycles. Existing Build 4D latest-week controlled correction remains its prior workflow; frozen Adapt/Learn copies do not change when that occurs.
17. **Persistence:** optional collections extend the existing `growth-engine.strategy.v1` envelope: `adaptReviews`, `cycleReviews`, `strategyChanges`, `strategyLearnings`, `strategicAssumptions`, `cycleResets`. Missing fields mean no records. Reading old builds does not fabricate or rewrite history. Existing compare-and-save transaction handles stale tabs/quota failures. System and Assessment stores are not written.
18. **Tests:** 299 passing tests, including 30 new Adapt/learning/reset tests covering requested A–U behavior, missing weeks, definition changes, explicit application, draft setup, downgrade prevention, rank swap audit, detached snapshots, carry dependencies, baseline reset, malformed records and Tehran midnight dates. TypeScript passed.

Test records remain in localhost for inspection.
20. **Dependencies:** none added. Existing Next.js, React, TypeScript, shared styling and UI components are used.
21. **Issues resolved:** date input events initially failed to retain browser-filled values; explicit input handling fixed this. Audited KR definition changes needed a new comparable weekly segment. Draft-cycle setup originally required a future Adapt review; this deadlock was removed while retaining controls after execution. 22. **Build 4F:** the final executive Strategy dashboard remains outside this build. Backend/auth, notifications, AI analysis and forecasting are also not implemented. Current persistence is browser-local; decision records are not a task engine or accounting system.

## Structure

- `lib/strategy/adapt/types.ts`: records and deterministic thresholds.
- `report.ts`: signals, evidence snapshots, quality and summaries.
- `mutations.ts`: save/complete/apply/close rules and provider transition checks.
- `definition.ts`: comparable measurement definitions and review date convention.
- `reset.ts`: frozen-source selection and fresh-cycle creation.
- `validation.ts`: additive persistence validation.
- `components/strategy/adapt-workspace.tsx` and `learn-workspace.tsx`: management workflows.
- `tests/adapt.cjs`: domain regression and integrity checks.

All browser mutations used `http://localhost:3000`; the separate `http://127.0.0.1:3000` user's data was preserved.
