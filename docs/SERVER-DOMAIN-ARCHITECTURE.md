# Server domain architecture — 7D work in progress

Approved connection: SaaS now uses the five fixed domain services and entity repositories; legacy server workspace JSON is retained as a recovery archive and coordination-version holder. Entity rows retain external IDs, versions, parent/owner/status fields and payloads, with messages stored separately. Nested histories remain inside their owning entity payload. Services reauthorize, validate scoped references, compare current state, apply shared Strategy/Scale transition guards and audit transactionally. Local mode remains explicit, and unbound SaaS storage throws instead of falling back. Agent business execution remains disabled. See [BUILD-7D-CONTINUATION.md](BUILD-7D-CONTINUATION.md) for current evidence and outstanding work; the following text records the earlier preview-only increment.

Current operational path: authenticated request → fresh organization/RBAC → validated workspace service → tenant-scoped PostgreSQL workspace document → audit. Browser memory is only an adapter cache; SaaS writes do not also write browser localStorage. Local mode retains existing local persistence.

The 7A normalized tables/repositories and initial domain services exist, but most operational v1 data still resides in the transitional workspace documents. Do not treat schema presence as completed domain migration. The 7D target is four canonical domain services that coordinate fresh permission checks, shared pure validation, transactional repositories, entity-level compare-and-swap and audit. UI providers must read canonical records through those services; derived health/report totals must use the existing pure selectors.

The newly added migration service provides scoped preview/lifecycle only. It cannot import or execute an Agent action. All import relationships must be mapped before adding execution. Legacy non-UUID IDs need a reversible, explicit mapping while preserving external IDs; silently replacing p6/d0-style IDs is prohibited.

The repository must preserve explicit assessment, System maps/SOP/KPI/history, Strategy check-in/snapshot/carry-forward, Scale actual/scenario/experiment lineage and Agent evidence/revision/approval/execution provenance. Historical local approval never grants server execution authority. Actor attribution must distinguish real server users from LegacyLocal historical actors.
