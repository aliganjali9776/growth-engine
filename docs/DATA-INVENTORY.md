## Relational migration decisions

Access Role means SaaS authorization, not `System.Role`, which represents a business job/ownership. User accounts are distinct from People; a Person can optionally link to a User, and archiving a Person never deletes the account. Every business root gains organizationId; child foreign keys carry organizationId as well to reject cross-company links at the database boundary. Global permissions/templates/default levers are reference data, not an organization's business records.

Core current business fields are relational columns; ordered collections become child tables. JSONB is reserved for immutable historical snapshots, validated heterogeneous Agent artifacts/command payloads, layout metadata and staged legacy exports. Staged raw exports are a migration archive, never the canonical operational database.

Export foundation captures every allowlisted raw store (including version/absence), module versions, source/export schema/version/time and company profile for exactly one explicitly selected local workspace. Future import must validate parsers, map every legacy ID consistently, validate all same-tenant links and actor provenance, then normalize in a transaction. No silent merge, automatic import or whole-store replacement is performed in 7A. Local schemas and browser behavior remain usable while later builds migrate individual services.
